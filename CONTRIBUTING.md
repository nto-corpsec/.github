# Как мы работаем

## Ветки

```
main                  # защищена: PR + 1 ревью + зелёный CI
feat/<role>/<slug>    # новая функциональность
fix/<role>/<slug>     # исправление
docs/<slug>           # документация
intel/<task-id>       # разведка и заметки
writeup/<task-id>     # разбор задачи
```

Префикс `<role>` — один из `lead`, `soceng`, `dfir`, `netsec`, `websec`, `osint`.
Ветка живёт не дольше 48 часов; если не успеваешь — разбей на части.

## Коммиты

Conventional Commits, английский, императив, ≤ 72 символа в заголовке:

```
feat(websec): add sqli payload generator
fix(dfir): handle empty evtx chunk
docs(hub): describe handoff ritual
```

Тело коммита — «почему», а не «что». Ссылка на issue: `Refs #12`.

## Pull Request

1. Заголовок = будущее сообщение в истории (squash-merge).
2. В описании: цель, что проверено, риски, как откатить.
3. Чек-лист в шаблоне обязателен.
4. Ревьюер — CODEOWNER затронутой зоны; для `main` — TeamLead.
5. Мержим только squash, ветку удаляем.

## Definition of Done

- [ ] CI зелёный, новых предупреждений нет
- [ ] Тесты/проверки на новое поведение добавлены
- [ ] Документация обновлена (README/runbook)
- [ ] Секретов, флагов и персональных данных в диффе нет
- [ ] Ссылка на issue и понятный план отката

## Ревью

- SLA: 2 часа в рабочее время, 12 часов ночью.
- Блокирующие замечания — только по делу: баг, безопасность, нарушение контракта.
- Стилистические придирки — в `nit:`, не блокируют мерж.
- Автор сам мержит после approve (кроме `ops`, там мержит лид).
