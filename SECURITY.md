# Политика безопасности

## Что никогда не попадает в git

| Категория | Пример | Куда вместо этого |
|---|---|---|
| Секреты | токены, пароли, приватные ключи | GitHub Secrets, локальный `.env` |
| Флаги и ответы | `flag{...}`, номера заданий | приватный `ops` |
| Персональные данные | ФИО, телефоны, почта участников | не коммитить вообще |
| Сырые артефакты | дампы, образы дисков, pcap > 5 МБ | `ops` + Git LFS, либо внешнее хранилище |
| Вредоносные сэмплы | бинарь, документ с макросом | изолированный стенд, никогда в git |

## Если секрет попал в публичный репозиторий

1. Немедленно отозвать/ротировать секрет у провайдера — до любых действий с git.
2. Написать в `#incident`, завести issue `priority/p0`.
3. Выполнить runbook `hub/runbooks/SECRET-LEAK.md`: очистка истории, force-push, проверка форков.
4. Записать в `ops/notes/incidents.md` время, причину, действия.

Помни: удаление файла коммитом **не удаляет** его из истории и не отменяет компрометацию.

## Сообщить об уязвимости в наших инструментах

Приватно TeamLead (`@eliald0`) или через Security Advisory репозитория. Публичные issue для
неисправленных уязвимостей не создаём.

## Область действия

Правила действуют для всех репозиториев организации, включая шаблоны и форки.
